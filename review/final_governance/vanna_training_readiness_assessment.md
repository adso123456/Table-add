**状态**: 只读评估，未训练 Vanna

## 评估维度

### 1. 当前注释覆盖率

| 指标 | 数值 |
|------|------|
| 字段注释覆盖率 | 83.1%（2863/3445） |
| 缺注释字段 | 582（16.9%） |

覆盖率已从 82.6% 提升至 83.1%，但仍有近 17% 字段无注释。这 582 个缺注释字段如果被纳入训练，Vanna 将无法为这些字段生成有意义的注释建议，反而可能产生噪声。

### 2. 剩余 582 个缺注释字段影响

| 子类 | 数量 | 风险 |
|------|------|------|
| B 档冲突字段 | 219 | 同名不同义，训练会学到错误关联 |
| C 档无证据字段 | 310 | 无任何依据，训练无法推理 |
| A 档 keep_manual | 3 | 空表/无外键，训练依据不足 |
| A 档 reject | 1 | 类型不匹配，训练会学到错误映射 |
| **合计** | **533** | |

注：582 - 533 = 49 个差额可能来自 B 档统计口径差异，以审计文件为准。

### 3. B 档 219 个冲突字段对训练的风险

**风险等级：高。**

219 个字段名在库内不同表中存在不同注释。例如 `code` 在表 A 表示"区域编码"、在表 B 表示"企业编码"。如果 Vanna 直接学习这些冲突，可能将错误的注释推荐给目标表。

**必须排除 B 档字段，或至少在训练数据中标注冲突。**

### 4. C 档 310 个 unsafe 字段对训练的风险

**风险等级：高。**

310 个字段在库内无任何同名字段有注释可参考。Vanna 无法从训练数据中学到这些字段的含义。强行训练只会产生幻觉注释。

**必须排除 C 档字段。**

### 5. 是否建议生成只读训练候选清单

**是。** 强烈建议在训练前生成：

- **白名单**：2863 个已有注释字段（has_comment=True）
- **黑名单**：582 个缺注释字段 + 219 个冲突字段名关联的所有表

### 6. 是否建议先做表级/字段级白名单

**是。** 建议以 `columns_with_comments.csv` 中 `has_comment=True` 的 2863 个字段为训练白名单基线，显式排除：

- `missing_comments.csv` 中的 582 个字段
- `comment_conflicts.csv` 中涉及的字段
- 所有 keep_manual 和 reject_candidate 字段

### 7. 是否建议冻结当前元数据快照

**是。** 建议在训练前保存当前元数据快照（summary.md + columns_with_comments.csv + tables_summary.csv），作为训练基线和回滚参考。

### 8. 是否需要业务方确认

**是。** B 档 219 个冲突字段和 C 档 310 个 unsafe 字段需要业务方逐表确认含义后才能纳入训练。

### 9. 是否允许训练 Vanna

**当前阶段：不允许。**

理由：
- 582 个缺注释字段可能污染训练数据
- 219 个冲突字段可能产生错误关联
- 310 个 unsafe 字段无法提供有效训练信号
- 4 个 A 档剩余字段未达到自动补注释标准
- 空表字段无法验证训练效果

**后续阶段：可在建立白名单和排除清单后，进行受限训练。**

### 10. 下一阶段建议

当前不建议直接全库训练。建议下一阶段先生成 Vanna 训练候选白名单和排除清单，只读评估，不写入 vanna_data，不训练。

具体步骤（不要在本阶段执行）：

1. 从 `columns_with_comments.csv` 提取 has_comment=True 的 2863 个字段作为白名单基线
2. 显式排除 missing_comments.csv 中 582 个字段
3. 显式排除 comment_conflicts.csv 中涉及的字段
4. 生成 `vanna_training_candidate_whitelist.csv`（只读，不写入 vanna_data）
5. 生成 `vanna_training_exclusion_list.csv`（只读，不写入 vanna_data）
6. 业务方确认白名单后，再进入 Vanna 训练准备阶段
7. **不要在本阶段执行任何训练操作**
